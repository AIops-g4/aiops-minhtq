# W2/D3 Serving Design

This service turns the W2/D1 correlation notebook and W2/D2 RCA notebook into a FastAPI endpoint. `serve.py` loads the service topology from `w2/d1/data/services.json` and incident history from `w2/lab_evidence-driven-remediation/data-pack/incidents_history.json` once at import time. The API receives raw alerts at `POST /incident`, validates them with Pydantic, converts them to plain dictionaries, runs correlation, chooses the largest cluster as the primary incident, then runs graph plus retrieval RCA.

The correlation config is fixed at `gap_sec=120` and `max_hop=2`, matching the D1 submission. Alerts close in time are grouped into sessions, then services are grouped by shortest-path distance on the service graph. Alerts whose `labels.note` contains `noise`, `unrelated`, or `independent` are forced into standalone clusters to avoid false correlation. The RCA stage ranks services using graph score, first-alert timing, and a payment connection-pool signal, then retrieves similar incidents from history to produce class, actions, and similar incident IDs.

The latency budget is measured at the API boundary with middleware. Every response gets `X-Response-Time-Ms`, and each request writes a JSON log containing method, path, status, and duration. In local warm benchmark, 20 sequential `/incident` requests had p50 `3.52 ms` and p99 `7.40 ms`; the first cold request after startup was about `296 ms`. The biggest cost here is graph scoring and Python startup/cold path, not LLM latency, because this implementation keeps `AIOPS_USE_LLM=false` by default.

`/healthz` and `/readyz` are intentionally separate. `/healthz` only proves the process can answer HTTP. `/readyz` verifies the graph and incident history are loaded and that the configured LLM mode is ready. If graph or history load fails, readiness should fail with `503` so a load balancer would not route real incident traffic to the process.

FastAPI is a better fit than Flask for this lab because Pydantic validation gives clean `422` errors for malformed alert payloads without manual `if` checks. It is also lighter than BentoML for this repo because the served unit is a full AIOps pipeline, not a single model artifact with model registry requirements.

The main production concern is concurrency and fault tolerance. The service keeps graph and history in process memory, so multiple uvicorn workers duplicate state. That is acceptable for this small dataset and makes single-worker local serving reliable on a weak machine. In a larger deployment, graph/history should be versioned and loaded from a shared store, and a real LLM call should always have timeout and fallback behavior. This version documents the LLM feature flag but does not call a provider because the D2 submission chose deterministic graph plus retrieval.
